## Read this before triaging

**The product is the memory lifecycle**, not the surfaces: context injected at session
start and across compaction, and memory that stays relevant — stale facts superseded rather
than re-injected forever. Weigh every item below by its distance from that, not by how
alarming its sweep line looks.

**What is verified WORKING** (`scripts/verify/probe_core_loop.py`, 14/14, re-run 2026-08-30
against a live gateway). Recorded here as `15/15` until 2026-08-31; that was never right —
the probe has had exactly fourteen `check()` calls at every revision, confirmed by parsing the
AST at both its introduction (`79e299c`) and today. Nothing regressed; the number was wrong
when written, and re-derived by nothing until it was:

- a newer contradicting fact supersedes the older one
- search and the profile return **only** current truth; the stale fact is gone from both
- supersession history is preserved (`truth_timeline` retains both versions)
- exactly one current version, and it is the right one
- `session-start` injects context carrying current truth and omitting stale truth
- context survives a compaction checkpoint intact, and is token-budgeted (`tokens_used=194`)

That is the hard part of a memory system, and it works.

**The one thing that breaks the promise is T1-1** — new memories do not form, so the proven
machinery has nothing to operate on. It has a validated one-line fix. **Everything else in
this document is secondary to landing it.**

Re-weighted consequences:
- **T1b-5 / T1b-4** (`forget_memory`, `correct_memory` dead over MCP) still matter — they are
  governance operations, reachable by operators honouring a correction or deletion request.
- **T1b-9 / T4-12** (18 dead admin routes, one tab rendering a 503 as false facts) drop
  furthest. They are an inspection surface; no core workflow runs through them.
- The Tier 0 items (T0-1 data loss, T0-2 crypto-shred) keep their rank — those destroy data
  rather than withhold a feature.
